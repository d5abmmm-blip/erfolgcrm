# Перенос данных из WinServisePro → ErfolgCRM

Загрузчик данных из старой программы **АКАМСОФТ «Сервис-Центр» (WinServisePro)**
(база Firebird 2.5, `data.fdb`) в ErfolgCRM (PostgreSQL).

Работает в два шага: **выгрузка** старой базы в один JSON-файл и **загрузка**
этого файла в CRM. JSON — это и есть «файл подгрузки»: его можно посмотреть,
сохранить и переносить отдельно от Firebird.

> ⚠️ JSON-выгрузка содержит персональные данные (ФИО, телефоны клиентов) в открытом
> виде. Храните её как конфиденциальный файл, не коммитьте в публичные репозитории.
> После успешной загрузки в прод её можно удалить.

---

## Шаг 1. Выгрузка (Firebird → JSON)

Читается **рабочая копия** базы (никогда не оригинал) через локальный сервер Firebird.

```powershell
# 1. Сделать копию базы по пути БЕЗ кириллицы (иначе сервер не открывает файл по сети).
Copy-Item "D:\...\WinServisePro\data.fdb" "$env:TEMP\wsp_data.fdb"

# 2. Поднять сервер Firebird 2.5 из комплекта WinServisePro (если ещё не запущен):
& "D:\...\WinServisePro\Firebird_2_5\bin\fbserver.exe" -a

# 3. Поставить зависимости и выгрузить:
cd scripts/import-winservice
npm install
$env:FDB_PATH="$env:TEMP\wsp_data.fdb"; node export-fdb.mjs
```

Результат — `winservice-export.json` рядом со скриптом.
Подключение по умолчанию: `127.0.0.1:3050`, `SYSDBA` / `masterkey`
(переопределяется через `FDB_USER` / `FDB_PASSWORD`).

## Шаг 2. Загрузка (JSON → PostgreSQL)

Загрузчик живёт в пакете БД (рядом с `seed.ts`), подключается как **owner** и обходит
RLS так же, как seed. Tenant — `erfolg` (должен существовать; создаётся seed-скриптом).

```powershell
# Сухой прогон — НИЧЕГО не пишет, только показывает план и примеры:
pnpm --filter @erfolg/db exec tsx src/import-winservice.ts --dry-run

# Реальная загрузка в dev:
pnpm --filter @erfolg/db exec tsx src/import-winservice.ts

# Загрузка в ПРОД — указать боевую строку подключения owner'а и ключ шифрования ПДн:
$env:DATABASE_OWNER_URL="postgresql://erfolg:...@prod-host:5432/erfolg"
$env:PII_ENCRYPTION_KEY="<боевой 32-байтный ключ>"
pnpm --filter @erfolg/db exec tsx src/import-winservice.ts path\to\winservice-export.json
```

> ⚠️ В прод `PII_ENCRYPTION_KEY` обязан совпадать с тем, которым CRM шифрует ПДн,
> иначе перенесённые ФИО/телефоны физлиц не расшифруются в приложении.

### Идемпотентность

У всех строк детерминированный `id` (UUIDv5 от старого ID), вставка через
`ON CONFLICT (id) DO NOTHING`. Повторный запуск ничего не дублирует и дольёт только
недостающее. Перенос дополняет данные CRM, существующие записи не трогает.

## Как ложатся данные (маппинг)

| WinServisePro | ErfolgCRM | Примечания |
|---|---|---|
| `CLIENT` | `clients` (+ `contacts`) | Тип (юр/физ) и бюджетник определяются по названию, `CLIENTTYPE`, ИНН и папке-группе. Папки-группы пропускаются. ФИО/телефон/адрес физлиц **шифруются**. Банковские реквизиты юрлиц сохраняются в `notes`. Контактное лицо (`CONTACTFACE`) → `contacts`. |
| `OUSER` | `users` | Роль: Администраторы→директор, Приёмщики→диспетчер, Мастера→инженер. Логины/пароли в старой базе зашифрованы и невосстановимы — заводятся новые логины (транслит ФИО) и **общий временный пароль `Erfolg-Import-2026`** (сменить при первом входе). |
| `OORDER` | `tickets` + `work_orders` | Номер заявки `WSP-<id>` (старый `ORDERNUMBER` неуникален — он в `notes`). Штрихкод из старого `BARCODE`. 12 старых статусов → 8 статусов CRM. Большинство — «Закрыта» (данные исторические). |
| `MODEL`/`MANUFACTURER`/`DEVICETYPE` + серийник заявки | `assets` | Техника создаётся из заявок и дедуплицируется по клиент+серийник+модель (один аппарат — одна карточка, общая для всех его ремонтов). |
| `WORKRECORD` / `DETAILRECORD` | `work_order_lines` (`work` / `part`) | Названия из справочников работ/деталей. Цены берутся как есть (в старой базе часто 0). |
| `STATUSHISTORY` | `ticket_events` (`status_change`) | Плюс событие `created` на дату приёма. |
| Суммы | копейки (`*100`) | Итоги берутся из материализованных полей заявки (`WORKSUM`/`DETAILSUM`/`ORDERSUM`). |

### Сознательные компромиссы

- **Платежи не переносятся как денежный реестр**: в старой базе оплаты заполнены у
  единиц заявок, а `PAYREG.QTY` содержит мусорные значения. Сумма оплат по заявке берётся
  из `OORDER.PAYSUM` (почти везде 0).
- **НДС/договоры/SLA** в старой базе отсутствуют → у перенесённых заявок НДС = «без НДС»,
  договоры не привязываются.
- Несколько организаций без узнаваемого названия и без ИНН могут попасть в «физлица» —
  поправляется вручную в карточке клиента.

## Файлы

- `export-fdb.mjs` — выгрузка Firebird → `winservice-export.json` (использует `node-firebird`).
- `winservice-export.json` — выгрузка («файл подгрузки»). Содержит ПДн — хранить аккуратно.
- `../../packages/db/src/import-winservice.ts` — загрузчик в PostgreSQL.
- `spike.cjs` — проверка подключения к Firebird (диагностика).
